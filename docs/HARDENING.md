# GraceFM-Ultra hardening plan

This document is a validation roadmap. Existing simulation and model metrics do not establish real SDR reception performance.

## Ten hardening stages

1. **Wire compatibility**
   - Consume shared golden bitstream vectors generated by GraceFM for all registered profiles and Haar/LeGall variants.
   - Test frame header, CRC, FEC, symbol mapping, soft-value polarity/scales, and recovered PCM.
   - Gate every GraceFM protocol revision on an explicit Ultra compatibility result.
2. **Model coverage and provenance**
   - Publish a machine-readable registry for profile, MendNet/PostNet hashes, training data manifest, training revision, ONNX opset, exporter/runtime versions, and validation metrics.
   - Missing models must be reported as unsupported; never silently substitute a model from another profile.
3. **Uncertainty calibration**
   - Measure predicted posterior standard deviation against empirical coefficient and waveform error.
   - Report calibration by profile, band, SNR, burst length, and channel model.
   - Add conservative fallback when uncertainty is out of distribution.
4. **Restoration safety**
   - Evaluate hallucination risk on transients, silence, speech, tonal signals, and unusual spectra.
   - Gate PostNet by calibrated uncertainty and observable signal quality.
   - Provide a deterministic decoder-only fallback that bypasses both networks.
5. **Channel-domain generalization**
   - Test AWGN, fading, Doppler, multipath, clock/frequency offset, impulsive interference, clipping, AGC transients, and packet bursts.
   - Keep train/validation/test source material disjoint and report domain-shift results.
6. **Streaming latency**
   - Measure queueing, MendNet lookahead, synthesis, PostNet context, ONNX invocation, and device I/O separately.
   - Enforce bounded queues and explicit overload/drop behavior.
7. **Runtime efficiency**
   - Benchmark per-profile CPU time, p50/p95/p99 latency, peak RSS, model-load time, and sustained thermal behavior.
   - Compare ORT execution providers and thread settings on target hardware.
8. **Input and model hardening**
   - Validate sample counts, frame counts, tensor dimensions, dtype, finite values, model metadata, and file hashes before inference.
   - Fuzz Rust parsing and Python data/model loaders.
9. **Reproducible training**
   - Record dataset manifests and content hashes, split manifests, RNG seeds, hardware/software versions, and complete hyperparameters.
   - Use fixed evaluation sets and promote models only through explicit quality gates.
10. **SDR integration and operations**
    - Validate RTL-SDR 8-bit I/Q handling, sample-rate limits, tuner/oscillator drift, AGC, USB overruns, and sustained operation.
    - Start with conducted RF and known attenuated signals; perform OTA testing only under applicable regulations.
    - Publish a supported device and operating-condition matrix.

## Model promotion gates

A profile model is deployable only when:
- its profile and codec revision match the receiver registry;
- its ONNX hash and metadata are recorded;
- ONNX/Python and Rust outputs pass numerical compatibility tests;
- it improves the fixed test set without unacceptable regressions on any protected category;
- p95/p99 compute time and memory remain inside the declared budget;
- decoder-only fallback remains available and tested.

## Current limitations to keep explicit

The checked-in ONNX models cover B200 and B200-L only. Other profiles require training/export/verification. The README's synchronized simulation path is not an RF acquisition implementation. Measured processing latency and memory should be reported with their exact machine and runtime configuration.
